Go 并发编程：从原理到模式

这套笔记整理自 O'Reilly 出版的《Concurrency in Go》（Katherine Cox-Buday 著）和本仓库附带的全部示例代码。 原书的脉络完整保留：为什么并发难 → Go 的并发哲学 → 基本构件 → 组合模式 → 大型系统里的实践 → 运行时如何调度。 每一章都配了大量示意图，把「看不见」的 goroutine、通道和调度过程画出来。

原书写于 2017 年，那时是 Go 1.8。此后 Go 在并发方面变化不少 —— 循环变量语义、泛型、WaitGroup.Go、context 的新函数、异步抢占、testing/synctest、goroutine 泄漏分析…… 凡是书中写法已经过时或有了更好选择的地方，笔记都用青色的 新版 Go 注释框标了出来，并在附录 B 汇总。

全书地图

这本书像一座五层的楼：最底层是「并发为什么难」的通用理论，往上是 Go 给出的答案（CSP 思想）， 然后是具体的语言构件，再往上是把构件组合起来的模式，最高层是把模式用在大型系统里。 第 6 章则是从地下室看这栋楼的地基 —— 运行时到底怎样把成千上万个 goroutine 跑在少数几个线程上。

这套笔记写给谁

  • 会写基本的 Go 代码（变量、函数、切片、结构体、接口、错误处理），但一碰到 goroutine 和通道就心里没底的人。
  • 写过并发代码，但总被「偶发 bug」折磨的人 —— 死锁、goroutine 泄漏、测试时好时坏。第 1、4、5 章就是为你写的。
  • 想知道书里的写法放到今天还对不对的人。每一处过时的地方都有新写法的对照。
ⓘ 前置知识

原书「不讲 Go 基础语法」。如果你对闭包（在函数里定义函数、并引用外面的变量）、defer、接口还不熟， 建议先过一遍 A Tour of Go。书里的例子大量使用「在 main 里定义匿名函数」的写法， 这只是为了让每个例子都能单文件运行，并不是推荐的工程组织方式。

怎么运行书中的例子

仓库里每个 fig-*.go 都是一个可以单独运行的程序，*_test.go 是测试或基准测试。建议用最新版 Go，并且一定试试 -race：

$ go version                      # 建议 Go 1.22 以上，最好是最新版
$ mkdir play && cd play && go mod init play
$ cp ../gos-concurrency-building-blocks/goroutines/fig-join-point.go main.go
$ go run .                        # 运行
$ go run -race .                  # 打开竞态检测器运行（第 1 章、附录 A）
$ go vet .                        # 静态检查，能发现不少并发误用
$ go test -bench=. -cpu=1 ./...   # 跑基准测试（第 3 章的上下文切换测试）
⚠ 运行老代码时会遇到的几个小问题
  • go.mod 里的 go 1.xx 版本号会改变语言语义：低于 1.22 时，第 3 章的「循环变量闭包」例子会重现书中的 bug；1.22 及以上则不会。
  • 书中用到的 io/ioutil 已弃用（Go 1.16 起），请换成 io.ReadAll、os.CreateTemp。
  • 仓库里 pipelines_test.go 和 fig-goroutine-leaks-example.go 的 import () 是空的，需要自己补上 testing、fmt。
  • 书中的随机数输出（如 5577006791947779410）是旧版 math/rand 固定种子的结果；Go 1.20 起全局随机源自动随机播种，你看到的数字会不一样。

💡 一句话总结

如果只能记住一件事：每启动一个 goroutine，都要想清楚它在什么时候、因为什么而结束。 这本书剩下的内容 —— done 通道、通道所有权、管道、context、心跳 —— 几乎都是在回答这个问题。
