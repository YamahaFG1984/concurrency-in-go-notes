从 Go 1.8 到今天

《Concurrency in Go》出版于 2017 年，对应 Go 1.8。书中的思想 —— 约束、通道所有权、done 通道、管道、错误即结果、心跳、限流 —— 至今依然是 Go 并发编程的基石； 变化的主要是写法和工具。这一页把散落在各章的「新版 Go」注释汇总起来，并给出一份老代码现代化清单。

没有变的东西

先强调一下：书里最重要的内容一点都没过时。

🔑

谁启动，谁负责停止

每个 goroutine 都要有退出路径。今天用 context 表达，原理和 done 通道完全相同。

🏠

通道所有权

创建、写入、关闭由同一个所有者负责，对外只暴露 <-chan。

📦

错误随结果一起返回

不要让 goroutine 自己打印错误了事。今天常用 errgroup 或泛型 Result。

📏

队列不提速

利特尔法则依然成立：队列是用延迟换稳定，只放在入口或批处理处。

🧠

锁还是通道

第 2 章的决策树依然适用：保护内部状态用锁，转移所有权和协调用通道。

💓

心跳与限流

生产环境的健康检查和令牌桶限流，思路完全不变。

老代码现代化清单

下面每一条左边是书中（Go 1.8 时代）的写法，右边是今天推荐的写法。很多条目可以用 go fix 自动完成（见本页末尾）。

1. interface{} → any 或泛型 1.18

书中写法
take := func(
	done <-chan interface{},
	valueStream <-chan interface{},
	num int,
) <-chan interface{} { ... }

toInt := func(...) <-chan int // 再写一个类型断言阶段
新写法
func Take[T any](
	ctx context.Context,
	in <-chan T,
	n int,
) <-chan T { ... }

// 不再需要 toInt / toString 阶段

2. 自制 done 通道 → context.Context 1.7

书中写法
done := make(chan interface{})
defer close(done)
for v := range stage(done, in) { ... }

// stage 内部
select {
case <-done:
	return
case out <- v:
}
新写法
ctx, cancel := context.WithCancel(ctx)
defer cancel()
for v := range stage(ctx, in) { ... }

// stage 内部
select {
case <-ctx.Done():
	return
case out <- v:
}

自己的纯信号通道，用 chan struct{} 而不是 chan interface{}。

3. 循环变量的副本 → 不再需要 1.22

书中写法
for _, s := range list {
	go func(s string) {
		fmt.Println(s)
	}(s)
}
// 或者：s := s
新写法（go.mod ≥ 1.22）
for _, s := range list {
	go func() {
		fmt.Println(s) // 每轮迭代独立的 s
	}()
}

4. wg.Add(1) + defer wg.Done() → wg.Go 1.25

书中写法
var wg sync.WaitGroup
for i := 0; i < n; i++ {
	wg.Add(1)
	go func() {
		defer wg.Done()
		work()
	}()
}
wg.Wait()
新写法
var wg sync.WaitGroup
for range n {
	wg.Go(work)
}
wg.Wait()

5. goroutine + 错误收集 + 取消 → errgroup

书中写法（第 4 章 Result 模式）
type Result struct {
	Error    error
	Response *http.Response
}
// 每个 goroutine 往 results 通道发 Result，
// 主 goroutine 统计错误、决定是否 close(done)
新写法（golang.org/x/sync/errgroup）
g, ctx := errgroup.WithContext(ctx)
g.SetLimit(10) // 可选：限制并发数
for _, url := range urls {
	g.Go(func() error { return fetch(ctx, url) })
}
err := g.Wait() // 第一个错误；出错时 ctx 被取消

需要逐个处理每个结果（而不是「第一个错误就全部取消」）时，书中的 Result 通道模式依然是好选择。

6. sync.Once + 变量 → OnceValue 1.21

旧写法
var (
	once sync.Once
	cfg  *Config
)
func getConfig() *Config {
	once.Do(func() { cfg = load() })
	return cfg
}
新写法
var getConfig = sync.OnceValue(load)

7. atomic.AddInt64(&x, 1) → atomic.Int64 1.19

书中写法
var left int32
atomic.AddInt32(&left, 1)
if atomic.LoadInt32(&left) == 1 { ... }
新写法
var left atomic.Int32
left.Add(1)
if left.Load() == 1 { ... }

8. pkg/errors 与类型断言 → 标准库错误包装 1.131.26

书中写法
if _, ok := err.(IntermediateErr); ok {
	msg = err.Error()
}
新写法
// 包装：fmt.Errorf("cannot run job %q: %w", id, err)
if e, ok := errors.AsType[IntermediateErr](err); ok {
	msg = e.Error()
}
// Go 1.26 之前：var e IntermediateErr; errors.As(err, &e)

10. 靠超时的并发测试 → synctest 1.25

书中写法
heartbeat, results := DoWork(done, nums...)
<-heartbeat // 等心跳，避免不确定的超时
for r := range results { ... }
新写法
synctest.Test(t, func(t *testing.T) {
	// 假时钟：Sleep、超时、Ticker 都瞬间且确定
	_, results := DoWork(done, nums...)
	for r := range results { ... }
})

11. 不需要并发的生成器 → 迭代器 1.23

通道生成器（有 goroutine，要考虑泄漏）
func Count(done <-chan struct{}, n int) <-chan int {
	out := make(chan int)
	go func() {
		defer close(out)
		for i := range n {
			select {
			case <-done:
				return
			case out <- i:
			}
		}
	}()
	return out
}
迭代器（没有 goroutine）
func Count(n int) iter.Seq[int] {
	return func(yield func(int) bool) {
		for i := range n {
			if !yield(i) { // 调用方 break 时返回 false
				return
			}
		}
	}
}

for i := range Count(10) { ... }

经验法则：阶段之间需要真正并发执行时用通道；只是想「一个一个地产出值」时用迭代器。

让工具帮你改：go fix 1.26+

Go 1.26 把 go fix 重写成了基于分析框架的「现代化」工具，内置了一组修复器，其中好几个正好对应本书的老写法。 下面是本笔记用 Go 1.27 对一段「书中风格」代码运行 go fix -diff 的真实结果： 

 func main() {
-	var n int64
+	var n atomic.Int64
 	var wg sync.WaitGroup
-	for i := 0; i < 3; i++ {
+	for i := range 3 {
 		i := i
-		wg.Add(1)
-		go func() {
-			defer wg.Done()
-			atomic.AddInt64(&n, int64(i))
-		}()
+		wg.Go(func() {
+			n.Add(int64(i))
+		})
 	}
 	wg.Wait()
-	var x interface{} = atomic.LoadInt64(&n)
+	var x any = n.Load()
 	fmt.Println(x)
 }

（应用后再运行一次，forvar 修复器会接着删掉多余的 i := i；所以可以反复运行直到 go fix -diff 不再输出。）与并发相关的修复器：

修复器作用
waitgroupgowg.Add(1) + go + wg.Done() → wg.Go
atomictypessync/atomic 函数调用 → 原子类型
forvar删除多余的 x := x 循环变量副本
rangeint三段式 for 循环 → for i := range n
anyinterface{} → any
errorsastypeerrors.As → errors.AsType[T]
testingcontext测试里的 context.WithCancel → t.Context()
slicessort基本类型的 sort.Slice → slices.Sort
⚠ 升级 go.mod 版本前先跑测试

把 go.mod 里的 go 版本从 1.21 以下升到 1.22+，会改变循环变量的语义；升到 1.23+ 会改变定时器行为；升到 1.25+ 会改变 GOMAXPROCS 默认值。 这些变化几乎总是修好 bug 而不是引入 bug，但为了保险：先在旧版本下跑一遍 go test -race ./...，升级后再跑一遍。
